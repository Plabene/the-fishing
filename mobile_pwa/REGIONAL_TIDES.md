# 지역별 물때 (2026-10-30)

## 원인과 변경

기존 웹은 관측소 DT_0025(보령)를 파서·API·저장·화면에 고정했다. PC에서 옮긴 158일 자료에는 2026/2027년 12월 1일만 경계일로 들어 있었고, 월 변경 시 공식 예보를 자동 요청하지 않았다. 따라서 남해를 선택해도 보령 자료를 표시하고 12월 대부분은 비어 있었다. 공식 API의 1년 조회 제한 때문에 생긴 현상이 아니다.

기존 더피싱 PC의 `boryeong_tide.py`는 월 양쪽 경계일을 포함한 고저조 자료에서 월별 상대 물흐름을 계산한다. 선상24 PC의 `regional_tide.py`는 서해=보령, 남해=여수, 동해=부산으로 분리한다. 웹은 이 계산과 권역 기준을 유지하고, 제주 및 시·도 대표 지점을 분리했다. 물흐름 %는 실측 유속이나 음력의 ‘몇 물’ 값이 아니다.

## 대표 지점

공식 조위관측소 운영 현황의 코드·명칭·좌표와 실제 조석예보 응답을 대조했다.

|선택 범위|대표 지점|코드|
|---|---|---|
|서해권|보령|DT_0025|
|남해권|여수|DT_0016|
|동해권|부산 (기존 PC 권역 기준)|DT_0005|
|제주권/제주특별자치도|제주|DT_0004|
|인천·경기|인천|DT_0001|
|충남|보령|DT_0025|
|전북|군산|DT_0018|
|전남 서해 지역|목포|DT_0007|
|전남 남해 지역|여수|DT_0016|
|경남|통영|DT_0014|
|부산·울산|부산|DT_0005|
|강원|묵호|DT_0006|
|경북|포항|DT_0091|
|제주 서귀포 세부 지역|서귀포|DT_0010|

이들은 권역/행정구역 대표 항구다. 개별 출항지에 가장 가까운 관측소라고 추정하지 않는다. 검증된 세부 규칙이 없으면 같은 권역의 명시된 대표 지점을 사용하며, 선택 지점의 날짜 자료가 없다고 다른 관측소 값을 가져오지 않는다. 지역 자체가 불명확하면 ‘기준 지점 미확인’으로 표시한다.

복수 지역에서는 현재 선택한 가장 구체적인 단계(출항지→세부지역→시도→권역)로 묶고, 실제 `tierQueryBoats`에 들어가는 지역·티어·플랫폼 조건의 선박 ID 수를 센다. 최대 척수 지역을 선택하고 동률이면 고정 지역 키 순서로 결정한다. 응답 성공 수, 잔여석, 출조 횟수, 어종은 투표 수에 영향을 주지 않는다. 플랫폼 간 선박은 기존 조회 시스템의 독립 ID 기준이며 실제 동일 선체라는 추측으로 합치지 않는다. 대표 지역과 기준 척수를 화면에 표시한다.

## 요청·저장·날짜

- API: `GET /v1/tides?month=2026-12&station=DT_0016`. 생략한 station은 기존 보령으로 호환된다. 허용 목록 외 코드·중복 파라미터는 거절한다.
- 브라우저는 월/대표 지점 변경 시 필요한 월과 앞뒤 경계일을 자동 조회한다. 빠른 변경은 이전 응답 적용을 취소한다. 실패 직후 반복 렌더링은 요청을 반복하지 않는다(60초 제한, 수동 갱신 가능).
- 원본은 공식 고저조 예보다. 날짜·지점명·코드(있을 때)·좌표(있을 때)·응답 건수·극치·조위를 검증한다. 한국 시간으로 일자를 연결한다.
- API 저장 키와 기기 저장 키는 모두 관측소+날짜/월이다. 기존 보령 자료와 백업 형식은 유지한다. 기기는 관측소별 최대 800일, 서버는 관측소별 인덱스 최대 1100개를 보존한다.
- 12시간 안의 공식 **예보** 자료만 재사용한다. 선박 잔여석 조회의 실시간 정책은 변경하지 않았다. 자료 수집 시각·과거 저장·경계일 부족을 표시한다.
- API는 중복 월 요청 합치기, 3개 일자 병렬/시작 간격 300ms, 20초 요청 제한, 일일 최대 2000일자 예산을 유지한다. 브라우저 요청 제한은 90초다. 날짜 미제공은 부분 응답으로, 인증/통신 장애는 일시 대기로 처리한다. 무한 재시도는 없다.
- 미래 1년 고정 컷오프는 없다. 2000~2099년 월 입력 중 제공처가 실제 제공한 날짜만 표시한다. 범위 끝에서 다음 달 경계일이 없으면 월 상대값은 근사임을 표시한다.

## 검증과 재현

`mobile.cmd test --maxWorkers=2`, `mobile.cmd build`, `mobile.cmd api:check`.

`tideRegion.test.ts`: 대표 척수, 다중 지역, 정규화, 플랫폼·티어, 중복 ID, 동률, 미확인 지역, 지역 간 저장 격리, 1년 이상 저장, 자동 로드 취소/실패.
`tideApi.test.ts`: 코드·날짜·좌표 검증, 관측소별 지속 캐시, 경계일, 2028 윤년, 부분 응답 및 누락 날짜 재조회.
`regionalTideParity.test.ts`: 공식 실자료 11지점 × 2026/2027년 12월, 기존 PC 계산과 날짜별 고저차·물흐름·등급 비교. 원본에서 얻지 못한 값은 fixture에도 넣지 않았다.
`tideUi.test.ts`와 브라우저 fixture: 월 이동, 자동 로드, 상세 날짜, 지역/티어 변경, 기존 예약·티어 보존. 브라우저 fixture는 명시적인 가상 자료이며 실제 예보 검증과 구분한다.

직접 원본 검증은 2026-10~2027-12의 매월 15일 표본과 2026/2027년 12월 전체 및 경계일, 총 869 관측소·날짜 조합이다. 854건 성공, 부산 2027-12의 4일은 503/시간초과, 11지점 2028-01-01은 미제공 코드 03이었다. 배포 API를 통한 월별 재검증 결과는 배포 보고서에 별도 기록한다. 모든 미래 날짜를 전수 검증한 것은 아니다.

## 배포·롤백

먼저 Worker를 배포하고 신규 station 응답 및 기존 month-only 호출을 확인한 후 Pages를 배포한다. 별도 선박 예약 API/개인 티어 스키마는 변경하지 않는다. 변경 전 소스는 Git 커밋 `340b5a3` 및 로컬 `.local/tide-regions/before.zip`에 있다. 문제가 있으면 해당 UI 커밋을 되돌려 Pages 재배포하고 Worker 이전 버전으로 롤백할 수 있다. 개인 IndexedDB/티어를 삭제하지 않는다.
