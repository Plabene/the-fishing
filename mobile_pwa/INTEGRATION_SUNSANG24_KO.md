### 실제 확인한 조회 문제

운영 페이지를 처음 열었을 때 브라우저가 예전 Service Worker의 캐시 우선 HTML을 사용하여 **선택 83척·처음 200척 제한·선상24 통합 전 UI**를 표시했다. 다시 로드한 뒤 최신 통합 화면이 보였다. 이를 PC 차단이나 선상24 전체 장애로 단정하지 않았다. 웹 진입은 네트워크 우선으로 바꾸고 오프라인일 때만 저장 HTML을 사용한다. 새 Service Worker가 활성화되면 ‘새 버전 열기’를 안내하며 진행 중 조회나 입력을 강제로 새로고침하지 않는다. IndexedDB 선박·티어 설정은 지우지 않는다.

공식 중앙 홈페이지는 동적 화면 셸이며 일반 HTML에 선박 목록이 포함되지 않는다. `api.sunsang24.com/robots.txt`의 `User-agent: * / Disallow: /`는 현재도 확인했다. 중앙 목록을 우회 수집하지 않으며 목록은 검증된 PC 카탈로그를 사용한다. 별도로 확인된 선사 홈페이지의 `/ship/schedule_fleet/YYYYMM`은 월·선박 ID·일정 ID·어종·명시적 잔여석을 포함하는 HTML이다. 이전에 구현한 공개 예약표 모듈을 유지했고 [도지호 11월 예약표](https://doji.sunsang24.com/ship/schedule_fleet/202611)와 운영 API를 다시 확인했다. 공개 예약표 연결 범위는 **380척 중 35척, PC 티어 21척 중 20척**이며 이번 UI 개선으로 미확인 주소를 추가하지 않았다. 별도 API 키 발급이 필요한 상태가 아니다.

## 분석 및 적용 범위 (2026-10-23)

더피싱은 TypeScript/Vite 정적 PWA, IndexedDB 개인 설정, Cloudflare Worker/Durable Object 조회 API 구조다. 선상24 PC의 `sunsang24_central_search.py`, `sunsang24_monthly.py`, `sunsang24_filter_schema.py`, `geographic_labels.py`를 분석했다. 중앙 월 조회는 정확한 하위 지역 ID 하나씩, 날짜 범위와 페이지 번호로 요청한다. total·고유 일정 수·날짜·지역이 일치해야 완전한 결과다. 선박별 선사 페이지 요청으로 바꾸지 않고 이 계약을 별도 TypeScript 모듈로 옮긴다.

## 지역 설계 대안

1. 원본 명칭 그대로: 가장 단순하지만 충남/충청남도, 보령/보령시가 갈라진다.
2. 모든 명칭의 접미사 제거·유사문자 매칭: 편리하지만 인근·섬·복수 지역을 잘못 합친다.
3. **출처를 보존한 명시적 정규화(선택)**: 검증한 시·도 별칭과 지역 코드/이름 쌍을 사용하고, 섬·항구는 상위 지역과 실제 출항지 근거가 있는 규칙만 적용한다. 불명확한 복수 지역은 원문을 남기며 미확인 항구를 만들지 않는다. 조회 시 고정 사전 조회이므로 추가 네트워크가 없다.

선상24의 `태안인근`, `보령인근`, `평택인근` 등은 실제 항구가 아니다. 항구 선택에서는 미확인으로 두고 원본 출항 구역으로 표시한다. 등록 지역 홍성/출항 구역 보령인근 같은 차이는 등록 지역으로 검색하고 양쪽 정보를 함께 노출한다. 정확한 항구 근거가 생기기 전에는 다른 시·군에 재분류하지 않는다.

더피싱의 경기도/인천 아래 오이도와 인천 항구는 같은 행정구역이 아니다. 항구 근거가 있는 항목만 경기도 시흥/인천으로 구분하고, 출항지 없는 인천 묶음은 분류를 유보한다. 개인 수정 자료는 원본 카탈로그 메타데이터로 덮어쓰지 않는다.

2026-10-23 `https://api.sunsang24.com/robots.txt`는 HTTP 200과 `User-agent: *`, `Disallow: /`를 반환했다. 기존 프로젝트 문서에도 이 제한과 과거 403이 기록되어 있다. 이용약관은 `https://app.sunsang24.com/customer/policy/service_termsofuse`에서 확인했다. 사용자는 허가·별도 API가 없음을 확인하고 가능한 통합부터 진행하도록 선택했다.

따라서 공개 선박 목록·필터·공식 페이지 연결을 제공하고 **선상24 실시간 자동 수집은 비활성화**한다. 현재 잔여석을 저장 자료로 대체하지 않는다. 중앙 조회 계약의 파서/페이지 검증/장애 격리는 비식별 테스트 응답으로 검증하며, 실제 API 계약 및 허용 범위를 재확인하기 전에는 활성화하지 않는다.

## 식별·예약 데이터와 오류 처리

선상24 신규 UID는 `sunsang24:ship:<ship_no>`, 일정 ID는 `sunsang24-schedule-<schedule_no>`다. 일정 번호가 없으면 PC와 같은 선박·날짜·출항시각·어종·요금 조합을 해시한다. 더피싱 UID/일정 ID는 그대로 유지한다.

동명 선박은 출항지·지역이 같아도 동일 선박 후보일 뿐이며 자동 병합하지 않는다. 플랫폼별 행·잔여석·상태·링크를 별도로 유지한다. 같은 선사의 URL 하나를 두 선박이 공유하는 경우도 있으므로 URL만으로 병합하지 않는다. 이미 저장된 선상24 외부 링크 4개만 PC의 명시적 선박 ID 연결과 정확한 이름·항구·URL이 모두 일치하여 기존 UID를 재사용한다.

공통 일정 모델에 원본 예약 상태와 날짜별 예약 페이지 URL을 추가했다. `remain_embarkation_num`에 실제 값이 없으면 `null`이다. 대기/마감이라는 이유로 0석을 생성하지 않으며, 양수 잔여석이 있더라도 예약 가능 상태가 아니면 인원 충족 결과에 넣지 않는다. 알 수 없는 상태·금액은 미확인이다. 0원도 무료라고 명시된 경우에만 0원으로 표시한다.

선상24는 별도 `sunsang24-v1` Durable Object로 분리했다. 실제 접근을 허용하는 변경을 하더라도 현재 지역 계층의 코드/명칭 검증 → 정확한 하위 지역 월 범위 → 모든 페이지/total/고유 일정 검증 순서를 거친다. 25초 제한, 1초 요청 간격, 분당 30개 원본 요청 예산, 최대 3개 대기 지역, 최대 20페이지/600개 일정 제한을 둔다. 한도를 넘거나 중간 페이지가 실패하면 일부 자료를 완전한 조회 결과로 표시하지 않는다. 더 큰 지역 결과의 날짜 분할 수집은 후속 작업이다.

401/403/429는 최소 10분 중단하며 다른 경로나 인증 수단으로 우회하지 않는다. 플랫폼별 중단과 예외를 격리하여 다른 플랫폼 결과는 계속 반영한다. 사용자의 전체 취소는 양쪽 조회를 중단한다. 잔여석은 저장 캐시로 대체하지 않으며, 클라이언트의 지역 응답 공유는 **조회 버튼 한 번의 실행 범위**에만 존재한다.

## 2026-10-23 추가 개선: PC 티어, 모바일 파일 백업, 전체 목록

위 통합 시점의 선택 해제 정책에 더해, 사용자 요청으로 PC의 선상24 티어 21척을 승계했다. 1티어 7척, 2티어 4척, 3티어 0척, 기타 10척이며 전부 공개 카탈로그의 ship ID와 일치한다. 동명인 가즈아호 2척도 ID 2068/307로 분리한다. 기본 목록은 1,057척, 초기 선택은 기존 83 + 21 = 104척이다. 개인 수정·삭제에 따라 실제 기기의 수는 다를 수 있다.

- `scripts/import-sunsang24-tiers.py`: PC preferences에서 티어 ID와 순서만 추출한다. ship ID를 웹 UID로 변환하며 미확인 ID가 있으면 저장하지 않는다. 원본 PC 파일은 변경하지 않았다.
- `src/data/sunsang24Tiers.json`, `src/sunsang24Tiers.ts`, `src/defaultFleet.ts`: 카탈로그 버전과 독립된 티어 적용 버전을 기록한다. 자동 승계는 아직 티어가 없는 선박만 채운다. 개인 티어·선택 해제·삭제를 다음 실행마다 덮어쓰지 않는다. 명시적인 PC 재적용 버튼은 PC의 21척만 재설정하며 되돌릴 수 있다.
- `src/tierBackup.ts`, `src/fileSave.ts`, `src/main.ts`: 티어 전용 JSON 저장/불러오기와 지원 기기의 파일 공유를 추가했다. 선택되지 않아도 티어에 배정된 선박을 포함한다. 백업 범위는 현재 화면 필터에 영향을 받지 않는다. 복원 시 포함된 UID의 티어·순서·선택 상태를 적용하고 다른 선박, 개인 이름, 월, 조회 자료를 유지한다. 없는 선박은 파일의 안전한 공개 필드로 추가한다. 중복·누락 ID 및 잘못된 형식은 전체 복원을 취소한다. 전체 자료 백업은 기존 버튼으로 별도 제공한다.
- `src/tierStore.ts`, `src/platforms.ts`, `src/main.ts`, `src/style.css`: `slice(0, 200)` 제한을 제거했다. 전체 목록의 정렬과 플랫폼 중복 후보 계산에 인덱스를 사용하고, DOM을 한 번에 교체한다. 월·물때·조회 결과만 바뀌면 목록 값 비교를 통해 행을 재사용한다. 모든 행은 문서에 존재하며 지원 브라우저는 화면 밖 행의 그리기를 생략할 수 있다.

새 파일 기능은 [MDN의 파일 공유 동작](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)과 [다운로드 속성](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download)을 확인해 구현했다. 공유/다운로드 요청과 실제 기기 저장 완료를 구분하는 안내를 사용한다. 공유 취소는 오류로 표시하거나 다운로드를 추가 실행하지 않는다.

검증: 34개 테스트 파일의 222개 테스트 통과, TypeScript 검사·Pages 경로 빌드·번들 검사 통과. 전체 선박 행 수, 200번째 이후 마지막 선박 수정, 선상24 380척 필터, 양 플랫폼 백업, UID 별칭, 순서/선택 복원, 변경 되돌리기, 잘못된 파일, 공유 취소, 기존 조회 기능을 확인했다. 새 UI 동작 테스트는 jsdom 기반이다. Work 설정에서 로컬 브라우저 제어가 꺼져 있어 이번 추가 화면 및 실제 휴대폰의 파일 저장 UI는 직접 검증하지 못했다. 실제 목록 표시 시간이나 조회 API 속도 개선 수치는 측정하지 않았다. API 호출/잔여석 처리 및 선상24 실시간 비활성 정책은 변경하지 않았다.

첫 CI 실행에서는 물때 UI 테스트가 5초 제한을 초과했다. 상태 저장 시 배열 참조가 복제되어 월·물때 변경에도 전체 선박 행을 다시 그리는 원인을 수정했다. 월 변경 시 기존 행이 유지되는 회귀 검사를 추가했으며 테스트 제한을 늘리거나 검사를 제외하지 않았다.

## 2026-10-23 조회 진단 및 캘린더 선박명 보완

사용자가 선상24 수집 실패와 캘린더 선박명 가림을 보고하여 재확인했다. 운영 Worker의 health는 `ready=true`, 선상24는 `permission_required`이며 월조회는 HTTP 200의 본문에 `PERMISSION_DENIED`를 반환한다. 웹·서버 양쪽의 비활성 설정이 원본 요청을 시작하기 전에 중단하는 직접 원인이다. API 호스트 robots.txt의 `Disallow: /`도 재확인했다. 이번에 선상24 월조회 원본에서 403을 받았다는 의미는 아니다. 실시간 연동을 활성화했다고 보고하지 않는다.

공식 홈페이지의 제휴 문의 이메일·고객센터를 확인했고, 공개 API 키 발급 포털이나 외부 월별 잔여석 API 명세는 찾지 못했다. 문의문, 확인할 항목, 승인 이후 기존 Worker에 연결하는 단계는 [API 진단·신청 안내](availability_api/README_KO.md#선상24-api-연동-진단과-신청)에 기록했다. 외부 문의 발송·새 계정 발급·비밀키 생성은 수행하지 않았다.

`calendarView.ts`에서 플랫폼 태그를 제거하고 선박명과 어종을 별도 요소로 나눴다. 기존 한 줄 말줄임 스타일 때문에 앞쪽 태그가 좁은 날짜 칸을 차지했던 문제를 수정하여, 선박명은 먼저 줄바꿈하고 어종은 그 아래에 표시한다. 관리·상세 결과의 태그는 유지한다. `queryDiagnostics.ts`에는 실제 수집 요청을 실행하지 않는 상태와 운영자용 연동 안내 링크를 추가했다.

35개 파일 225개 테스트, TypeScript 검사·운영 빌드·번들 검사 통과. 양 플랫폼 이름 표시, 캘린더 태그 부재, CSS 줄바꿈, 날짜 선택·월 변경, 비활성 안내와 공식 링크를 검증했다. CSS는 jsdom 계산 스타일로 확인했으며 실제 렌더링 크기나 휴대폰 실기기 화면은 로컬 브라우저 도구가 Work 설정에서 비활성화되어 확인하지 못했다.
