# 티어 복구와 군산 선박 목록 보완 — 2026-10-26

## 확인한 원인과 미확인 부분

개인 티어는 서버 데이터베이스나 GitHub에 저장되지 않는다. 기기 브라우저의 IndexedDB `thefishing-mobile-a` / `local` / `state`에 저장됐다. 서버는 공개 선박 메타데이터와 예약 조회 API를 제공한다. 사이트 캐시 갱신은 IndexedDB 삭제 작업을 하지 않는다.

소스에서 재현한 문제는 다음과 같다.

1. 이전 배포 티어 적용 함수가 버전 표시가 없는 기존 기기에서도 1,057개 선박 범위의 개인 티어·선택을 배포 기본값으로 교체했다. 이전 백업에서 버전 표시가 빠진 경우도 해당했다.
2. 기기 자료 읽기에 실패해도 빈 상태로 편집을 계속 허용했다. 이후 저장이 기존 자료를 덮어쓸 위험이 있었다.
3. 상태를 단일 키로 저장해 오래 열린 다른 탭의 저장을 구분하지 못했고, 같은 배포 버전의 보호 백업도 다시 덮어썼다.
4. 티어 파일 내보내기는 티어 없이 선택만 한 선박을 임의로 `기타`에 추가했다. 마지막 백업의 선택 선박 중 10개가 해당한다.

위 경로는 자동 테스트로 재현·수정했다. 그러나 문제가 발생한 휴대폰의 당시 IndexedDB와 실행 기록에 접근하지 못했으므로 **실제 소실 사건의 단일 원인을 확정한 것은 아니다.** 직전 목록 갱신 커밋 자체는 배포 티어 JSON을 변경하지 않았다.

티어 배열의 순서와 선택 배열이 원본·배포 복구 자료·휴대용 복구 파일 사이에서 정확히 일치함을 검증했다. 모든 대상의 선박 식별 정보가 있어 미복원 대상은 0개다. 원본 전체 백업과 예약 기록은 배포하지 않고, 복구에 필요한 선박 메타데이터·티어·선택만 포함했다.

- 기존 기기의 티어가 완전히 비었고 백업의 티어 선박 모두가 목록에 있으면 한 번 자동 복구한다. 이후 사용자가 의도적으로 비운 티어를 재생성하지 않는다. 개인 목록이나 삭제한 선박이 있는 경우 자동으로 강제 복구하지 않는다.
- **선박 추가·수정 · 티어 백업 → 티어 복구 · 자동 보호 이력**에서 마지막 백업 또는 이 기기의 자동 보호 이력을 선택할 수 있다.
- **누락 티어만 복구**는 현재 지정한 티어와 선택을 유지한다.
- **백업 분류·선택 적용**은 백업에 담긴 선박 범위에만 해당 분류·선택을 적용한다. 다른 선박과 조회 자료는 유지한다. 현재 이름·항구 수정도 유지한다.
- **선택한 복구 파일 저장**으로 휴대폰에 JSON을 저장할 수 있다. 새 휴대용 백업은 버전 2이며 티어 미지정 선택 선박을 그대로 보존한다. 기존 버전 1 파일 가져오기도 지원한다.
- 의도적으로 티어를 비운 예전 전체 백업을 가져온 경우에도 그 선택을 존중하며, 다음 실행에서 자동 복구로 덮어쓰지 않는다.
- 복구 전 상태는 자동 이력으로 보관한다. 개인 티어·선택·관련 선박 메타데이터는 별도 `personal-preferences-v1` 키에 저장하고 상태/이력/버전을 하나의 트랜잭션으로 처리한다. 오래된 탭의 덮어쓰기는 거부하고 새로고침을 안내한다. 읽기 실패 시 변경을 막고, 저장 실패 시 기존 상태와 이력을 유지한다.

휴대폰 자체가 아직 새 버전을 실행하지 않았다면 실제 기기 복구가 완료됐다고 볼 수 없다. 브라우저 자료 삭제는 하지 말고 업데이트/새로고침 후 복구 결과를 확인해야 한다. 보호 이력도 같은 기기 저장소에 있으므로 브라우저 데이터 삭제·기기 분실에 대비한 JSON 파일 백업은 계속 필요하다. 다른 개인 설정 전체를 복원하려면 보관한 원본 전체 백업의 기존 가져오기 기능을 사용할 수 있다.
