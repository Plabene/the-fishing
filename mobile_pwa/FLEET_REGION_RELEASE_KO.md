## 확인된 원인

1. 선상24의 종전 380개 목록은 PC 프로그램의 누적 학습 카탈로그에서 가져온 값이었다. 전국 목록을 완전히 수집한 결과가 아니었으며 군산 항목이 없었다. 정기 갱신도 더피싱 목록만 대상으로 했다.
2. 더피싱의 전체 검색은 676개 카드·34페이지를 반환했지만, 이번 실제 검사에서 고유 UID는 428개였다. 페이지 사이에 248개 카드가 중복됐다. 공개 검색 폼에서 확인한 지역 37개를 각각 끝 페이지까지 조회하자 추가 UID 175개를 확인해 이번 확인 합계는 603개가 됐다. 기존 보유 목록과 비교한 신규 UID는 7개다.
3. 저장된 검색 조건과 선박 데이터의 행정구역 표기가 다르면 누락될 수 있었다. 조건과 데이터 양쪽에 같은 정규화를 적용했다.
4. 군산낚시프라자의 큰 월 예약표는 기존 4 MB 제한에 걸렸다. 또한 선사 공지 안에 복사된 과거 달력 HTML이 있어 일정 ID·날짜·잔여석 선택자가 잘못된 영역까지 읽었다. 12 MB 상한을 적용하고 공지·메모 하위 트리를 구조화된 일정 파싱에서 제외했다. 실시간 잔여석은 실제 현재 월 표에서만 읽는다.

근거: [더피싱 공개 목록](https://thefishing.kr/reservation/list.php), [군산낚시프라자 공개 예약표](https://gunsannaksi.sunsang24.com/ship/schedule_fleet), 기존 PC `state/sunsang24/boat_catalog.json`과 `data/sunsang24/web_vessel_catalog.json`. 원본 HTML·예약자 데이터는 저장소에 추가하지 않았다.

## 적용한 구조

- `src/regionNames.ts`, `regions.ts`: `전북`, `전라북도`, `전북특별자치도`를 같은 시도로 처리한다. 강원·제주 등 다른 시도 약칭과 단일 시·군·구 접미사도 정규화한다. 여러 지역이 합쳐진 명칭을 임의로 분리하지 않는다.
- `scripts/lib/catalog.mjs`, `scripts/update-fleet.mjs`, `availability_api/catalog.ts`: 공개 검색 폼의 실제 지역 코드만 사용한다. 전체·지역별 모든 페이지를 수집하고 총 카드 수, 페이지 수, 반복 페이지, 응답 지역·시각을 검증한다. 충돌한 정보는 임의로 선택하지 않고 기존 자료를 보존한다.
- `src/data/sunsang24CatalogSources.json`, `scripts/lib/public-fleet.mjs`, `scripts/update-sunsang-fleet.mjs`: 검증한 선사 주소·지역 근거·선박별 항구만 사용한다. 예약표 내 선박 탐색 목록도 읽어 해당 월 일정이 없는 선박을 보존한다. 공지에 복사된 달력·탐색 버튼은 제외한다.
- `availability_api/sunsang24Public.ts`, `worker.ts`: 고정된 공개 선사 주소만 받는 목록 API를 추가했다. 임의 URL·중복 파라미터를 거부하며, 목록 캐시는 식별·지역 정보만 24시간 유지한다. 월별 잔여석은 매 조회마다 원본을 새로 읽는다.
- `src/main.ts`, `platforms.ts`, `regionFilter.ts`, `defaultFleet.ts`: 전체·플랫폼·지역 집계에 동일한 ID 중복 제거 기준을 적용했다. 티어 미등록, 출항지 미확인, 일정 연동 가능 여부를 구분한다. 지역·플랫폼 전환은 기존 목록만 필터링하며 재수집하지 않는다.
- `.github/workflows/deploy.yml`: 기존 월요일 06:17 KST 실행에서 두 목록을 각각 갱신한다. 한 플랫폼이 실패해도 다른 플랫폼의 성공 결과를 사용할 수 있다. 실패·충돌을 실행 요약에 남기고 검증·빌드 후 GitHub와 Pages에 반영한다.
- `scripts/import-sunsang24-catalog.py`: 나중에 PC 목록을 다시 가져와도 공개 선사에서 추가한 항목이 사라지지 않도록 합친다.

지역은 원본 등록 지역과 확인한 선사 주소를 근거로 한다. 선사 주소는 실제 출항 항구와 구분해 안내하고, 특정 선박의 현재 안내에서 확인한 항구만 별도 저장한다. 구룡호는 제주 시도만 확인했고, 엔에스호·꽃돼지호(참돔)·까치선장 까치호의 확정 세부 지역은 임의로 지정하지 않았다. 이 항목들은 전체 지역/미확인에서 찾을 수 있다.

같은 플랫폼·동일 ID만 하나로 집계한다. 플랫폼이 다른 경우 정규화한 이름·항구·시도·세부 지역이 모두 같을 때만 동일 선박 **후보**를 표시하며 자동 병합하지 않는다. 플랫폼별 잔여석과 예약 링크를 합산하거나 섞지 않는다.

기존 개인 티어, 선택, 이름·항구 수정, 직접 추가/삭제한 선박, 조회 자료와 백업 형식은 유지한다. 신규 선박은 자동 선택하지 않는다. 배포용 기본 티어·선택 배열과 사용자의 별도 배포 설정 JSON이 변경되지 않았음을 비교했다.

- 군산의 세 가지 전북 표기로 같은 두 플랫폼 결과가 검색됨을 검증했다. 부안·통영·강릉·포항·제주 지역도 선상24 검색을 검증했다.
- 실제 앱 DOM 테스트에서 지역별 행 수와 플랫폼 버튼 수의 일치, 선상24 티어 등록·선택 저장, 월 변경, 추가 요청 없는 플랫폼 전환을 확인했다.
- 기존 달력·어종·물때·실시간 새 조회·백업·개인 수정 보존 테스트와 목록 누락/반복/중복/충돌, 접근 제한·타임아웃·부분 실패, 출처 검증 테스트를 실행했다. 최종 실행 결과는 배포 커밋의 Actions에서 확인할 수 있다.
- 2026-10-26 10:55 KST 운영 API에서 블랙핑크호(선상24)와 어청도피싱호(더피싱)의 11월 일정이 `fresh=true`, `cached=false`로 응답했다. 11:07 KST 프로호·포항 빈스·강릉 동원호도 정상 응답했다.
- 11:09 KST 군산낚시프라자의 수정된 11월 파서는 실제 17개 ID·621개 출조 일정을 읽었다. 이는 예약 가능한 선박 621척이라는 뜻이 아니다. 예약 마감 등 원본 상태도 포함한 일정 수다.
- TypeScript/Vite 빌드, 직접 조회 번들 검사 및 Worker 배포 검증을 수행했다. 기존 큰 JS 번들 경고는 남아 있다. 실제 휴대폰 터치·화면 검증이나 새 속도 비교 수치는 이번 결과에 포함하지 않는다.

**전국 완전 수집은 확인하지 못했다.** 선상24 중앙 API는 현재 연동 이용 허가가 없고 `robots.txt`가 자동 접근을 제한해 호출하지 않는다. 공개 선사 목록에 없는 중앙 등록 선박은 별도 허용된 공식 목록/API가 필요하다. 공개 선사 `seil`, `haeinho`, `hyunju`는 이번 목록 검증에 실패해 기존 항목을 유지했다. 더피싱의 페이지 간 중복·정보 충돌도 남아 있어, 미노출 항목을 삭제하지 않고 확인 시각과 수집 범위를 기록한다.

