# 티어가 조회 대상에서 사라져 보이는 문제 점검 (2026.10.26.6)

## 확인 범위와 원인

사용자는 선박 선택·관리의 분류 변경이 아니라 **달력 또는 조회 대상에서 선박이 안 보이는 상황**이라고 확인했다. 휴대폰의 IndexedDB에는 직접 접근하지 못했으므로 해당 기기의 데이터 삭제 여부를 확정하지 않는다.

직전 다중 티어 UI에서 `전체 → 1티어`를 누르면 전체 집합에서 1티어를 빼는 동작이 있었다. 선택한 티어가 오히려 조회 대상에서 제외되며 이 조건은 새로고침 후에도 저장됐다. 이 동작을 코드와 재현 테스트로 확인했다. 조회 조건 변경은 `selectedTiers`를 바꿀 뿐 지정 티어 `tiers`를 삭제하지 않는다.

## 첨부 백업 대조

`thefishing-tiers-2026-10-26T05-04-43-137Z.json`의 선박 139개를 저장소의 복구 자료와 비교했다. 선박 ID·이름·항구·URL 차이 0, 중복 선박 ID 0이었다. 티어별 ID·순서와 선택 선박 목록은 현재 복구 자료 및 배포 기본 분류와 일치했다.

| 구분 | 지정 티어 | 그중 조회 선택 |
|---|---:|---:|
| 1티어 | 17 | 17 |
| 2티어 | 25 | 24 |
| 3티어 | 31 | 31 |
| 기타 | 56 | 51 |
| 합계 | 129 | 123 |

백업에는 별도로 미분류지만 선택된 10척이 있어 선택 선박 합계는 133척이다. 지정 티어가 있지만 선택되지 않은 6척도 원본 그대로 보존한다. 이 차이를 임의로 고치거나 백업으로 사용자의 현재 설정을 일괄 덮어쓰지 않았다.

## 수정 사항

- `src/tierStore.ts`, `main.ts`: 전체 상태에서 특정 티어를 누르면 그 티어로 선택을 시작한다. 이후 다른 티어는 추가/해제한다. 전체 상태에서는 전체 버튼만 강조한다.
- `src/tierVisibility.ts`, `appLayout.ts`, `main.ts`, `css/filter-panels.css`: 기기에 저장된 티어별 개수를 조회 결과와 별도로 표시한다. 숨겨진 이유를 선박 선택 해제, 티어 필터, 지역·플랫폼, 정보 누락으로 구분한다. 합계가 중복 집계되지 않도록 첫 제외 원인만 센다.
- `조회에서 안 보이는 선박 확인 → 조회 필터 해제`: 티어·지역·플랫폼·어종·검색어 조건만 해제한다. 지정 티어, 선택한 선박, 인원 조건, 저장 관측 자료는 바꾸지 않는다. 새 잔여석은 `조회하기`로 다시 확인한다.
- 같은 영역의 `티어·백업 확인` 링크로 기존 보호 이력·백업 비교를 열 수 있다. 자동으로 복구를 실행하지 않는다.
- `src/appUpdate.ts`: 버전 2026.10.26.6.

## 검증

로컬 전체 검사 56파일 334개 통과. TypeScript/Pages 빌드, 번들 검사, API dry-run 통과.

새 테스트 `tests/tierVisibility.test.ts`, `tests/tierVisibilityUi.test.ts`는 전체→단일→복수→해제, 빈 필터 저장 후 재시작, 필터 해제 후 대상 복원, 실제 API 요청 대상의 ID(mock 응답 사용), 날짜별 표시, 원본 백업 129척의 집계, 설정 저장·재읽기·월 변경·목록 초기화 후 티어/선택 보호, 조회 조건만 바꿀 때 개인 설정 이력이 불필요하게 바뀌지 않는 것을 확인한다.

실제 휴대폰 저장소와 모바일 화면은 브라우저 제어가 비활성화되어 확인하지 못했다. 이 변경을 해당 기기의 티어를 복원 완료했다는 의미로 보고하지 않는다. 원본 수집 API와 기본 티어 데이터 파일은 수정하지 않았다.
