## 확인한 조회 원인과 수정

### 팀한프로

- 제공된 백업에는 `external:3e13428ab1e484d50b7e`가 1티어로 선택되어 있지만, 10월·11월 모두 `unsupported_source` 실패만 있었다.
- 기존 웹 클라이언트는 숫자 더피싱 UID만 지원하여 이 외부 식별자를 요청하지 않았다. 이 누락이 확인된 오류 원인이다.
- 기존 PC 프로그램의 `external_site_profiles/teamhanpro.json`에서 `vendor_boat_id: 5364`, 예약 동작 `popup.step1.php`, 일치 조건 `PA_N_UID`를 확인했다. 2026-08-04에 저장된 검증 기록도 같은 사이트·프로필을 가리킨다.
- `bookingAliases.ts`에 해당 식별자만 명시적으로 연결했다. 기존 API에 `uid=5364&month=...&fresh=1`을 요청하고 검증을 통과한 결과의 UID를 원래 외부 UID로 돌려준다. 선박명·출항지·지역·티어·선택·기존 기록은 바꾸지 않는다.
- 예약 페이지는 검증된 더피싱 연결 페이지를 사용한다. 원래 홈페이지 URL은 선박 속성에 보존한다. 플랫폼 분류도 기존 `외부 사이트`를 유지하므로 팀한프로는 `전체`에서 조회된다.
- 다른 UID, 요청 월 불일치, 오래된 관측 시각, 캐시 응답은 거절한다. 실패한 경우 원래 홈페이지를 반복 요청하지 않는다.

### 청남호

- 청남호는 기존 더피싱 UID `1441`이며 뉴청남호 `5951`과 별개다. 제공된 백업에도 청남호 조회 자료가 있고 실패 기록은 없었다.
- 이번 운영 API 검증에서는 10월과 11월 모두 정상 응답했다. 사용자가 경험한 과거 조회 실패는 재현하지 못했으므로 원인을 확정하지 않았다. 기존 청남호 수집 파서는 변경하지 않았다.
- 청남호 독립 홈페이지는 이 PC에서 HTTP 403, HTTPS는 호스트명과 인증서 불일치가 발생했다. 팀한프로 독립 홈페이지도 HTTP/HTTPS 403이었다. 인증서 검증을 끄거나 접근 제한을 우회하지 않았다.
- 따라서 현재 독립 홈페이지의 DOM·JavaScript·세션 내부까지 검증한 것은 아니다. PC 프로필의 식별자 근거와 실제 작동 중인 더피싱 예약 응답을 구분해서 사용했다.

## 제공 JSON 적용과 복원

첨부 백업의 1,057척은 기존 카탈로그와 UID 및 모든 선박 속성이 일치했다. 중복 UID, 티어 간 중복, 알 수 없는 티어 UID는 없다.

| 분류 | 척수 |
|---|---:|
| 1티어 | 15 |
| 2티어 | 18 |
| 3티어 | 28 |
| 기타 명시 분류 | 52 |
| 티어에 명시된 합계 | 113 |
| 선택한 선박 | 118 |

선택 목록과 티어 목록은 서로 다른 데이터다. 선택한 선박 중 티어 배열에 없는 10척은 임의 배정하지 않았다. 기존 앱의 표시 규칙에 따라 미지정 선박도 기타 필터에 포함되므로 화면의 기타 수는 명시된 52척과 다를 수 있다.

`publishedPreferences.json`에는 선박 UID 범위·티어 순서·선택·버전만 담았다. 전체 백업의 관측 5,160건, 실패 이력, 기타 개인 데이터는 새 기본 자료로 게시하지 않았다.

업데이트를 처음 연 기기는 적용 전 티어·선택을 IndexedDB의 별도 키에 백업한 후 분류를 적용한다. 같은 버전에서는 다시 덮어쓰지 않는다. 직접 추가한 선박과 수정한 선박 속성은 유지하고, 삭제한 선박을 다시 생성하지 않는다. **선박 추가·수정 · 티어 백업 → 이번 기본 티어 적용 전으로 복원**으로 이전 티어·선택을 복원할 수 있다. 기존 파일 내보내기·공유·가져오기도 유지한다.

향후 파일 교체는 저장소 루트에서 실행한다.

```powershell
python scripts/publish-fleet-preferences.py --input '새 전체 백업.json'
.\mobile.cmd test
$env:PWA_BASE='/the-fishing/'
.\mobile.cmd run build
```

새 파일에 알 수 없는 선박이나 수정된 속성이 있으면 스크립트는 오류로 중단한다. 이름으로 추측하여 매칭하거나 속성을 버리지 않고 카탈로그 변경을 먼저 검토해야 한다.

## 검증 및 배포 절차

- 자동 테스트 **43개 파일 / 257개 테스트 통과**. 팀한프로 연결·잘못된 응답 거절·다른 선박의 정상 결과 유지, 현재 월 시작·월 이동·날짜 선택, 티어 정확 적용·1회 마이그레이션·설정 복원·관측 자료 보존을 추가 검증했다.
- 기존 지역·플랫폼·어종 다중 필터·물때·오류·취소·백업·파서·원본 새 조회 테스트도 통과했다.
- TypeScript 검사, Pages 경로용 정적 빌드와 번들 검사, Worker dry-run 검사를 통과했다.
- 360·375·390·430px 및 태블릿·PC의 실제 렌더링 검증은 **미실시**다. 사용자 승인 이후에도 도구가 `Local browser use is disabled in Work settings`를 반환했다. DOM 자동 테스트와 CSS 검토를 실제 화면 검사로 간주하지 않았다.
- 변경 전 Git 커밋 `04736365f0504b3afdcc0b5661a37f68ce6e71b6`을 로컬 `backup/pre-calendar-adapters-20261023` 브랜치로 보존했다. 배포는 `main`의 GitHub Actions 테스트·빌드·Pages 단계로 수행한다. Worker는 변경이 없어 재배포하지 않는다.
- 코드 롤백은 해당 릴리스 커밋을 `git revert`한 뒤 같은 검증·배포를 수행한다. 개인 티어는 코드 롤백만으로 되돌아가지 않으므로 위 설정 복원 또는 개인 JSON 백업을 사용한다.

선상24 기존 35척의 검증된 공개 예약표 연결은 유지되며, 확인되지 않은 나머지 선박이 이 변경으로 새로 지원되는 것은 아니다. 접근 제한 시 자동 우회·무한 재시도는 하지 않고 실패 단계·상태와 공식 링크를 제공한다. 사용자가 조회하기를 다시 누르면 새 요청을 보낸다.
