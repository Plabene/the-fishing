# TheFishing 월별 예약 조회

저장소: https://github.com/Plabene/the-fishing

GitHub Pages: https://plabene.github.io/the-fishing/

이 저장소는 GitHub Pages 모바일 웹앱과 Cloudflare 월별 조회 API를 함께 관리합니다. 기존 PC 선박 목록 512척과 선택 83척·티어를 유지합니다.

## 월별 예약 조회

어종 선택에서 원하는 어종을 **여러 개 체크**하면 그중 하나라도 포함된 출조를 표시합니다. **전체 어종**은 전체 결과를 복구하고 **선택 해제**는 체크를 모두 해제합니다. 복합 출조는 중복 표시하지 않습니다. **어종 포함·제외**는 PC 프로그램처럼 항목을 옮겨 결과를 걸러내며, 모바일에서는 한 번 누르면 이동합니다. 달력의 선박 표시와 날짜 상세·월 전체 목록에 어종별 색상과 이름을 표시합니다. 쭈꾸미/주꾸미·쭈/갑·쭈꾸미&갑이 등 실제 출조명 표기를 정규화하고, 복합 출조는 각 어종으로 검색할 수 있습니다. 어종 변경은 원본 조회 자료를 보존하고 추가 요청 없이 적용하며 월 변경·앱 재실행·백업 복원 후에도 선택을 유지합니다.

API 조회는 최대 3척씩 진행하고 동일 요청을 합칩니다. 월 변경 시 검증된 상세 페이지 정보를 1시간 재사용하며, 같은 선박·월의 성공 결과는 서버와 현재 화면에서 10분간 재사용합니다. 원본 요청 최소 1초 간격과 접근 제한 시 중단은 유지합니다. 조회 완료 메시지에 소요 시간을 표시합니다. 실제 측정과 검증 범위는 [어종·성능 개선 기록](mobile_pwa/ACCESS_FEASIBILITY_REPORT_KO.md)에 있습니다.

주 화면에서 **조회 월 → 출조 인원 → 조회 API 사용 → 실시간 월 조회**를 선택합니다. API가 더피싱 공개 달력을 읽어 날짜별 출조 상품과 잔여석을 반환합니다. PC를 켜둘 필요가 없습니다. 개인이 예약한 내역을 기록하거나 예약을 실행하는 기능은 없습니다.

2026-10-22 본인 Cloudflare 계정에 API를 배포하고 기본 주소 `https://thefishing-availability.thefishing-mobile-a.workers.dev`를 연결했습니다. 이전 임시 주소를 저장한 기기는 새 기본 API로 자동 전환합니다. 사용자 지정 다른 API와 명시적인 연결 해제는 유지합니다.

2026-10-22 08:01:54 KST에 본인 계정의 클라우드 API에서 UID 6130의 2026-10 출조 상품 5개 조회에 성공했습니다. 웹앱 출처에 대한 CORS 헤더와 재조회 시 캐시·관측 시각 유지도 확인했습니다. 이 검증은 해당 선박·월에 대한 결과이며 모든 선박의 조회 성공을 보장하지 않습니다.

새 API 주소는 **조회 API 연결 → 연결 확인 및 저장**으로 설정합니다. 기기별 선박 목록·티어·기존 자료는 유지합니다. 실패 시 원본/서버 오류, 미지원, 미조회 결과를 구분하고 이전 자료를 보존합니다. 취소 시 완료한 선박만 반영합니다. 진단 복사와 공식 달력 링크도 제공합니다.

**저장 자료 검색**은 기기에 있는 이전 자료를 검색합니다. 초기 자료는 2026-10-01 15:49:07 KST까지 PC에서 수집한 2026-10 출조 상품 1,744건이며, 현재 잔여석을 보장하지 않습니다. API 성공 결과는 해당 선박·월을 교체합니다. **브라우저 직접 조회**는 CORS 진단용으로 유지하며, 기존 직접 조회 실패가 해결된 것으로 간주하지 않습니다.

API는 고정된 더피싱 조회 경로만 사용하며 원본 요청을 순차 처리합니다. 10분 공유 캐시, 요청 간격·처리량 제한, 접근 제한 시 중단을 적용합니다. 로그인·예약·결제·자격 증명 전송은 없습니다. 외부 사이트 선박은 공식 페이지를 이용합니다. 자세한 구조·배포 명령·제한은 [조회 API 안내](mobile_pwa/availability_api/README_KO.md)에 있습니다.

## 개발과 검증

```powershell
.\mobile.cmd install --frozen-lockfile
.\mobile.cmd test
.\mobile.cmd run build
.\mobile.cmd run api:check
```

자동 테스트는 API 연결 UI, 서버·브라우저 파서, CORS 허용 출처, 임의 URL 차단, 캐시·제한·오류·취소·기존 자료 보존을 확인합니다. 실제 운영 조회는 자동 테스트에서 실행하지 않습니다. 클라우드 API HTTP 실검증은 별도로 완료했으며 실제 휴대폰 화면 렌더링 검증은 브라우저 도구 비활성화로 수행하지 못했습니다.

## PC 선박 목록 승계

2026-10-21에 PC에 저장된 기본 선박 506척과 활성 외부 선박 5척·소속 선박 1척을 포함한 512척을 기본 목록으로 반영했습니다. 선택한 83척과 1티어 10척·2티어 10척·3티어 20척·기타 43척의 순서를 유지합니다. 한글 식별자를 쓰는 팀베테랑호와 외부 사이트를 쓰는 팀한프로도 포함합니다.

처음 방문하거나 이전 버전에서 비어 있던 기기는 자동으로 기본 목록을 받습니다. 이미 선박을 편집한 기기는 기존 자료를 유지합니다. `PC 선박 목록 적용`으로 PC 기본 선택·티어를 다시 적용할 수 있으며, 기존 출조 기록과 직접 추가한 선박은 유지하고 바로 되돌릴 수 있습니다. 이후 PC 변경사항이 자동 동기화되지는 않습니다.

기본 목록의 선박명·항구·공식 URL·선택·티어는 정적 웹앱에 포함되어 사이트 방문자에게 보입니다. 쿠키·연락처·예약 신청자·PC 경로·예약 실행 코드는 기본 자료에 넣지 않습니다. 월별 출조 상품의 잔여석·요금·관측 시각은 아래 공개 조회 자료에 포함합니다. 기기에서 편집하거나 가져온 자료는 해당 브라우저에만 저장됩니다.

`공식 사이트에서 현재 잔여석 확인`에서 선택 선박의 공식 예약 페이지를 새 탭으로 열 수 있습니다. API가 지원하지 않는 선박이나 조회가 실패한 경우에도 이 링크를 사용할 수 있습니다.

PC 목록을 나중에 다시 반영할 때는 명시적으로 원본 state 경로를 지정합니다. 아래 도구는 지정된 4개 목록·설정 파일에서 허용 필드만 추출하고, 새 외부 출처가 발견되면 검토 없이 포함하지 않습니다.

```powershell
.\mobile.cmd exec node scripts/sync-fleet.mjs 'PC 프로그램 폴더\state'
.\mobile.cmd test
.\mobile.cmd run build
```

## Windows 개발 환경

Codex에서 `D:\the-fishing` 폴더를 프로젝트로 열고 작업합니다. Node.js 24와 잠금 파일에 지정된 pnpm 10.28.2를 사용합니다. `mobile.cmd`는 Codex에 포함된 런타임을 먼저 사용하며, 없으면 PATH에 설치된 Node.js와 pnpm을 사용합니다. 명령은 자동으로 `mobile_pwa`에서 실행됩니다.

PowerShell에서:

```powershell
Set-Location 'D:\the-fishing'
.\mobile.cmd install --frozen-lockfile
.\mobile.cmd test
.\mobile.cmd run build
.\mobile.cmd run preview --port 4173 --strictPort
```

마지막 명령이 실행 중일 때 http://127.0.0.1:4173 에서 완성된 화면을 확인합니다. `Ctrl+C`로 종료합니다. 소스를 수정한 뒤에는 다시 빌드하고 화면을 새로 고칩니다. 이 미리보기는 로컬 PC 개발용입니다.

GitHub Pages와 같은 경로로 검증하려면 빌드와 미리보기 실행 전에 다음 값을 설정하고 http://127.0.0.1:4173/the-fishing/ 에 접속합니다.

```powershell
$env:PWA_BASE='/the-fishing/'
```

루트 주소의 로컬 미리보기로 돌아가려면 `$env:PWA_BASE='/'`로 설정하고 다시 빌드합니다.

## 수정과 배포

주로 `mobile_pwa/src`를 수정하고, 아이콘과 서비스 워커 등 정적 파일은 `mobile_pwa/public`에서 관리합니다. `dist`는 자동 생성된 빌드 결과입니다. 기존에 업로드했던 `dist`는 Git 추적에서 제외했습니다. GitHub Actions가 소스에서 새로 빌드하므로 생성 파일을 직접 업로드하지 않습니다.

작업 전 Git 상태와 원격 변경 내용을 확인하고, 수정 후 테스트·빌드와 변경 내용을 검토합니다. `.github/workflows/deploy.yml`은 `main`에 푸시되면 새로 빌드하여 GitHub Pages에 배포합니다. 개발 환경 준비만으로 원격 저장소나 배포 사이트가 바뀌지는 않습니다.

이 폴더에서 커밋할 Git 작성자 이름·이메일이 아직 설정되지 않았다면 본인의 정보를 저장소 범위로 설정하세요. 푸시 인증은 GitHub 연결과 별도로 Git Credential Manager 로그인 여부에 따라 필요할 수 있습니다.

```powershell
git config --local user.name '본인 이름'
git config --local user.email '본인 GitHub 이메일 또는 GitHub 비공개 이메일'
```

PC 원본 프로젝트의 개인 자료·쿠키·로그를 이 공개 저장소에 복사할 필요는 없습니다. 앱 사용 안내는 [mobile_pwa/README_MOBILE_A_KO.md](mobile_pwa/README_MOBILE_A_KO.md)를 참고하세요. 현재 개발·배포 절차는 이 문서를 따릅니다.
