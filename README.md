# TheFishing 월별 예약 조회

저장소: https://github.com/Plabene/the-fishing

GitHub Pages: https://plabene.github.io/the-fishing/

이 저장소는 `mobile_pwa` 정적 웹앱의 개발용 저장소입니다. 조회 버튼을 누르면 사용 중인 브라우저가 더피싱 월 달력을 직접 요청합니다. 서버·PC 수집기 없이 동작하며, 실제 성공 여부는 해당 기기의 응답으로 판정합니다. 자동 예약은 제공하지 않습니다.

## 월별 예약 조회

주 화면에서 **조회 월 → 출조 인원 → 브라우저 직접 조회 → 실시간 월 조회**를 선택합니다. 저장 자료만 검색하려면 조회 방식을 **저장 자료 검색**으로 바꿉니다. 티어·선박·항구·어종으로 범위를 좁히고, **달력** 또는 **월 전체 목록**으로 날짜별 출조 상품을 볼 수 있습니다. 달력의 날짜 또는 목록의 날짜 제목을 누르면 선박별 상품·조회 당시 잔여석·요금·기준 시각을 표시합니다. 개인이 예약한 내역을 기록하는 기능은 없습니다.

처음 포함되는 저장 데이터는 **2026년 10월 1일 15:49:07 KST까지 PC에서 조회한 2026년 10월 자료**입니다. `2026년 10월 자료` 버튼으로 해당 월을 바로 엽니다. 원본의 인원 조건별 캐시 200개에서 선박별 가장 넓은 완전한 조회 범위(1명)를 선택해 출조 상품 1,744건을 반영했습니다. 선택 83척 중 81척에 조회 이력이 있고, 상품이 있는 선박은 75척입니다. 나머지 2척의 미확인 상태는 별도로 표시합니다. 조회 결과가 없다는 이유로 예약 마감이라고 표시하지 않습니다.

**직접 조회는 PC 오류와 독립적으로 현재 기기에서 실행합니다.** 2026-10-21 사용자가 PC에서 404가 발생하지만 모바일에서는 정상 접근 가능하다는 가정으로 직접 조회 구현을 요청하여, 이전의 오프라인 전용 구성을 변경했습니다. 모바일 성공을 사전에 가정하여 성공 상태를 표시하지는 않습니다.

상세 GET에서 선박 UID와 읽기 전용 달력 주소를 확인하고 `date6=YYYYMM`, `st_uid`, `pa_uid`를 달력 POST로 보냅니다. 원래 달력 요청의 `X-Requested-With` 헤더를 사용하며 브라우저가 필요한 CORS 사전 요청을 처리합니다. 쿠키·인증정보는 보내지 않으며 Origin/Referer/Cookie 위조, `no-cors`, 프록시, 로그인·예약 실행은 없습니다. `https://thefishing.kr/reservation/list.php`와 검증된 달력 파일 2개만 연결을 허용합니다.

선박은 순서대로 하나씩 조회하며 요청 간격은 최소 1초, 각 요청 제한 시간은 15초입니다. 성공한 선박·월은 같은 탭에서 10분간 재사용합니다. 페이지 로드/새로고침/백그라운드에서는 자동 수집하지 않습니다. 404는 해당 선박의 HTTP 실패로 표시하고 차단이라고 단정하지 않습니다. 401/403/429, 보안 확인 화면, 네트워크/CORS 판정 불가 오류는 연속 조회를 중단합니다. 403/429/보안 화면 이후 같은 탭에서는 10분간 추가 요청을 중지합니다. 실패한 선박의 이전 자료는 보존하며 취소 시 이미 성공한 선박의 결과만 반영합니다.

숫자 UID를 가진 더피싱 상세 주소 선박만 직접 조회합니다. 외부 사이트·운영사 페이지 선박은 미지원으로 표시하고 공식 링크를 제공합니다. **공식 페이지가 휴대폰에서 열리는 것과 GitHub Pages에서 응답 본문을 읽는 것은 다릅니다.** 실제 사이트가 배포 출처 `https://plabene.github.io`의 CORS 요청을 허용해야 합니다. 브라우저가 본문을 숨긴 경우 원인을 CORS로 단정하지 않고 네트워크/CORS/리디렉션 판정 불가로 표시합니다. [MDN CORS 설명](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)

성공 시 조회 시각과 직접 조회 표시를 붙입니다. 외부 HTML의 스크립트·예약 동작은 실행하지 않습니다. 실제 선박·월·숫자 잔여석을 검증하며, 잘못된 달력이나 미확인 값은 예약 마감으로 처리하지 않습니다. 앱을 다시 열거나 JSON을 가져온 자료는 저장 자료로 취급합니다.

기본 월별 자료는 사이트에 공개되는 정적 데이터입니다. 최초 업데이트 때 기존 기기 자료와 병합하고, 더 새로운 관측값과 선박 선택·티어를 유지합니다. 같은 기본 자료를 다시 주입하지 않으며, 삭제한 선박을 복구하지 않습니다. 이후 PC에서 정상 조회한 자료는 **PC 조회 결과 가져오기 · 백업**을 펼쳐 `monthly_availability_cache.json`을 가져올 수 있습니다. 가져온 자료도 자동으로 실시간 자료가 되지 않습니다.

개발자가 PC의 정상 조회 결과를 공개 웹의 기본 데이터로 갱신할 때는 다음 명령을 사용한 뒤 테스트·빌드·커밋·푸시합니다. 스크립트는 파일만 읽으며 운영 사이트를 조회하지 않습니다.

```powershell
.\mobile.cmd exec node scripts/sync-monthly.mjs 'PC 프로그램 폴더\state'
.\mobile.cmd test
.\mobile.cmd run build
```

이번 변경의 자동 검증은 71개 테스트와 GitHub Pages 경로 빌드입니다. 상세 GET→달력 POST, 허용 주소, 월/UID 검증, 잔여석·상품 파싱, 401/403/404/429/보안 화면, 타임아웃·취소·부분 성공과 직접 조회 버튼을 모의 응답으로 검증했습니다. 운영 사이트에 실제 조회 요청은 보내지 않았습니다. 월/인원/티어/검색 조건, 미확인·실패 상태, 기존 데이터 보존, 백업 왕복, 화면 버튼의 DOM 통합 동작을 검증합니다. 실제 모바일 브라우저 렌더링 검증은 브라우저 도구 비활성화로 수행하지 못했습니다.

## PC 선박 목록 승계

2026-10-21에 PC에 저장된 기본 선박 506척과 활성 외부 선박 5척·소속 선박 1척을 포함한 512척을 기본 목록으로 반영했습니다. 선택한 83척과 1티어 10척·2티어 10척·3티어 20척·기타 43척의 순서를 유지합니다. 한글 식별자를 쓰는 팀베테랑호와 외부 사이트를 쓰는 팀한프로도 포함합니다.

처음 방문하거나 이전 버전에서 비어 있던 기기는 자동으로 기본 목록을 받습니다. 이미 선박을 편집한 기기는 기존 자료를 유지합니다. `PC 선박 목록 적용`으로 PC 기본 선택·티어를 다시 적용할 수 있으며, 기존 출조 기록과 직접 추가한 선박은 유지하고 바로 되돌릴 수 있습니다. 이후 PC 변경사항이 자동 동기화되지는 않습니다.

기본 목록의 선박명·항구·공식 URL·선택·티어는 정적 웹앱에 포함되어 사이트 방문자에게 보입니다. 쿠키·연락처·예약 신청자·PC 경로·예약 실행 코드는 기본 자료에 넣지 않습니다. 월별 출조 상품의 잔여석·요금·관측 시각은 아래 공개 조회 자료에 포함합니다. 기기에서 편집하거나 가져온 자료는 해당 브라우저에만 저장됩니다.

`공식 사이트에서 현재 잔여석 확인`에서 선택 선박의 공식 예약 페이지를 새 탭으로 열 수 있습니다. 직접 조회를 지원하지 않는 선박이나 조회가 실패한 경우에도 이 링크를 사용할 수 있습니다. 모바일에서의 실제 GET/POST·CORS 성공 여부는 아직 확인되지 않았습니다.

PC 목록을 나중에 다시 반영할 때는 명시적으로 원본 state 경로를 지정합니다. 아래 도구는 지정된 4개 목록·설정 파일에서 허용 필드만 추출하고, 새 외부 출처가 발견되면 검토 없이 포함하지 않습니다.

```powershell
.\mobile.cmd exec node scripts/sync-fleet.mjs 'PC 프로그램 폴더\state'
.\mobile.cmd test
.\mobile.cmd run build
```

## Windows 개발 환경

Codex에서 `D:\the-fishing` 폴더를 프로젝트로 열고 작업합니다. Node.js 24와 잠금 파일에 지정된 pnpm 10.28.2를 사용합니다. `mobile.cmd`는 Codex에 포함된 런타임을 먼저 사용하며, 없으면 PATH에 설치된 Node.js와 pnpm을 사용합니다. 명령은 자동으로 `mobile_pwa`에서 실행됩니다.

PowerShell에서:

```powershell
Set-Location 'D:\the-fishing'
.\mobile.cmd install --frozen-lockfile
.\mobile.cmd test
.\mobile.cmd run build
.\mobile.cmd run preview --port 4173 --strictPort
```

마지막 명령이 실행 중일 때 http://127.0.0.1:4173 에서 완성된 화면을 확인합니다. `Ctrl+C`로 종료합니다. 소스를 수정한 뒤에는 다시 빌드하고 화면을 새로 고칩니다. 이 미리보기는 로컬 PC 개발용입니다.

GitHub Pages와 같은 경로로 검증하려면 빌드와 미리보기 실행 전에 다음 값을 설정하고 http://127.0.0.1:4173/the-fishing/ 에 접속합니다.

```powershell
$env:PWA_BASE='/the-fishing/'
```

루트 주소의 로컬 미리보기로 돌아가려면 `$env:PWA_BASE='/'`로 설정하고 다시 빌드합니다.

## 수정과 배포

주로 `mobile_pwa/src`를 수정하고, 아이콘과 서비스 워커 등 정적 파일은 `mobile_pwa/public`에서 관리합니다. `dist`는 자동 생성된 빌드 결과입니다. 기존에 업로드했던 `dist`는 Git 추적에서 제외했습니다. GitHub Actions가 소스에서 새로 빌드하므로 생성 파일을 직접 업로드하지 않습니다.

작업 전 Git 상태와 원격 변경 내용을 확인하고, 수정 후 테스트·빌드와 변경 내용을 검토합니다. `.github/workflows/deploy.yml`은 `main`에 푸시되면 새로 빌드하여 GitHub Pages에 배포합니다. 개발 환경 준비만으로 원격 저장소나 배포 사이트가 바뀌지는 않습니다.

이 폴더에서 커밋할 Git 작성자 이름·이메일이 아직 설정되지 않았다면 본인의 정보를 저장소 범위로 설정하세요. 푸시 인증은 GitHub 연결과 별도로 Git Credential Manager 로그인 여부에 따라 필요할 수 있습니다.

```powershell
git config --local user.name '본인 이름'
git config --local user.email '본인 GitHub 이메일 또는 GitHub 비공개 이메일'
```

PC 원본 프로젝트의 개인 자료·쿠키·로그를 이 공개 저장소에 복사할 필요는 없습니다. 앱 사용 안내는 [mobile_pwa/README_MOBILE_A_KO.md](mobile_pwa/README_MOBILE_A_KO.md)를 참고하세요. 현재 개발·배포 절차는 이 문서를 따릅니다.
